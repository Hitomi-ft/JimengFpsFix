# 帧率修复工具 (JimengFpsFix)

把即梦 / Dreamina 导出的「24.08 帧」视频**无损**修复成精确的 **24.000 fps**，并保证音频对齐。
支持一次多选 / 拖拽 / 整目录批量处理。

---

## 1. 为什么会出现 24.07 / 24.08 帧

对示例文件逐帧分析后可以确定：**内容本来就是 24 fps，只是时间戳被写坏了。**

* 视频流共 **169 帧**，时间基 1/15360；精确的 24 fps 应当是每帧 **640** tick。
* 实际每帧间隔在 **512 / 768** tick 之间交替（84 个 512 + 84 个 768）——这是把真实的
  640 tick 四舍五入到 **1/60 秒（256 tick）网格**上造成的抖动。
* 169 帧里有 169 帧都精确落在 `round(n × 640 ÷ 256) × 256` 上，误差为 0；
  也就是说 **每帧的显示时刻 ≈ n/24 秒**，内容确实是 24 fps。
* 但容器声明时长比真实内容短，于是 `帧数 ÷ 时长` 得到 24.0x，各种软件读到的就是它。

**这个数字随帧数变化，本质是同一个毛病**（同一种抖动、169/193 帧实测）：

| 帧数 | 48 | 96 | 144 | 169 | 193 | 240 |
|---|---|---|---|---|---|---|
| ffprobe 报的帧率 | 24.2017 | 24.1004 | 24.0669 | **24.0855** | **24.0748** | 24.0401 |

所以工具**从不读取这个数字**，只判断时间戳结构；24.07 和 24.08 走的是同一条无损路径。

结论：不需要重新编码，**只需要把时间戳写回精确的 1/24 秒网格**。

## 2. 修复原理与两种模式

| 模式 | 做法 | 结果 |
|---|---|---|
| **无损重写时间戳**（默认，自动优先） | 视频流 `-c:v copy`，用 `setts` 位流过滤器把每帧 PTS/DTS 重新对齐到精确网格；音频 `-c:a copy` | 帧数不变、画面**零损失**（逐帧比特一致）、秒级完成 |
| **重编码**（自动回退） | `libx264 -crf 16`；接近目标帧率时保留全部帧重新计时，差距大时用 `fps` 过滤器做标准帧率转换 | 适用于时间基无法整除、时间戳不在网格上等源 |

**音频对齐**的处理：

* 无损模式下视频内容的时间轴完全不变（每帧偏差 ≤ 8 ms，且不累积），因此音频
  **原样复制**、起始时间保持 0 —— 对齐关系与源文件完全一致。
* 只有当视频时长真的发生变化（>0.5%，例如 30→24 保留全部帧的变速修复）才会用
  `atempo` 同步变速音频，保证唇音同步。
* 可选择「与视频等长（填充/裁剪）」让音频尾部与视频严格等长。

**每个文件都会重新探测校验**（`校验` 不是可选项）：

1. 输出帧率必须**精确等于**目标值（含容器元数据 `avg_frame_rate`）；
2. **每一帧时间戳都必须落在目标网格上**，且间隔均匀 —— 这同时证明了没有丢帧 / 复制帧 / 乱序；
3. 帧数与源一致（非标准转换模式下）；
4. 音频起始时间必须与源一致、时长不能无故缩短；
5. 可选完整解码校验（默认开启）。

任何一项不通过 → 自动改用重编码；结果先写临时文件，**校验通过后才改名落地**，
不会留下半成品。

## 3. 交付物

```
dist\JimengFpsFix.exe   图形界面版（双击运行，推荐）
dist\fpsfix.exe         命令行版（批量脚本 / 以后做流水线用）

src\                    源代码（C# / .NET 9 WinForms，无第三方依赖）
build.ps1               重新构建

raw\2.mp4   raw\3.mp4   原始样本（各 193 帧，24.0748 fps）

```

## 4. 使用方法（图形界面）

1. 双击 `dist\JimengFpsFix.exe`。
2. 添加文件：**「添加文件…」可一次多选**，或「添加文件夹…」整目录（含子目录），
   或者直接把文件 / 文件夹**拖进窗口**；也可以把文件直接**拖到 exe 上**打开。
3. 默认设置即可（目标 24、自动（优先无损）、音频自动）。列表上方会显示每个文件的
   源帧率与帧数，方便确认。
4. 点「开始修复」。每个文件都会显示：修复方式、结果（是否 24 fps、音频是否原样）、输出文件名。
5. 输出默认写在源文件同目录，文件名加后缀 `_24fps`（可改；也可指定输出目录或覆盖源文件）。

界面右下角可设置：目标帧率（24 / 23.976 / 25 / 29.97 / 30 / 60 或直接填 `24000/1001`）、
修复方式、重编码质量 CRF / preset、并行文件数等。设置会自动记住。

> 已达标文件会自动**跳过**（避免重复处理）；需要强制重做时勾选「已达标文件也重新处理」。
> ffmpeg 路径：程序会自动在自身目录、PATH、scoop / choco / winget 目录里查找；
> 找不到时可点「选择 ffmpeg…」手动指定。

## 5. 使用方法（命令行 / 批量）

`fpsfix.exe` 是控制台程序，在 PowerShell 里会正常等待并输出结果（退出码 0 成功 / 1 有失败 / 2 参数错误）：

```powershell
# 单个文件（输出到同目录，加 _24fps 后缀）
dist\fpsfix.exe raw\jimeng.mp4

# 整目录批量、输出到指定目录、2 个文件并行
dist\fpsfix.exe --out D:\fixed --parallel 2 "D:\jimeng_batch"

# 覆盖源文件（校验通过后才替换）
dist\fpsfix.exe --overwrite "D:\jimeng_batch"

# 只允许无损模式（做不到就报错，绝不重编码）
dist\fpsfix.exe --method copy raw\jimeng.mp4

# 目标 23.976 fps，并把日志写到文件
dist\fpsfix.exe --fps 23.976 --log run.log "D:\batch"
```

主要参数：`--fps` `--method auto|copy|encode` `--encode auto|keep|conform`
`--audio auto|copy|tempo|fit` `--out` `--suffix` `--overwrite` `--crf` `--preset`
`--parallel` `--force` `--no-deep-verify` `--no-recursive` `--ffmpeg` `--log` `-q`；
`--help` 查看完整说明。

GUI 版也支持命令行：`dist\JimengFpsFix.exe --cli raw\jimeng.mp4`（从 PowerShell 调用时
建议重定向输出到文件，或用 `cmd /c`，因为 GUI 子系统的程序不会被 PowerShell 等待）。

## 6. 实测验证结果

三个真实样本（`raw\1.mp4` 169 帧 24.0855 fps，`raw\2.mp4` `raw\3.mp4` 各 193 帧 24.0748 fps）
全部走**无损重写时间戳**，逐帧用 ffprobe / framemd5 复核：

| 项目 | 1.mp4 源 → 修复 | 2.mp4 / 3.mp4 源 → 修复 |
|---|---|---|
| `avg_frame_rate` | 10140/421（24.0855）→ **24/1** | 11580/481（24.0748）→ **24/1** |
| `r_frame_rate` | 60/1 → **24/1** | 60/1 → **24/1** |
| 帧数 | 169 → **169**（一帧不多一帧不少） | 193 → **193** |
| 视频时长 | 7.016667 s → **7.041667 s**（= 169/24） | 8.016667 s → **8.041667 s**（= 193/24） |
| 每帧时间戳 | 512/768 抖动 → **640 均匀**（0,640,…,107520） | → **640 均匀**（0,640,…,122880） |
| 解码帧内容 | — | **逐帧 MD5 完全一致**（画面零损失） |
| 音频 | aac 44100 | **比特级完全一致**，起始 0、时长不变 |
| 耗时 | — | 约 1 秒 / 文件 |

另外已验证：25 / 30 fps 源（自动改走标准帧率转换，时长与音频不变）、无音轨、
已达标文件跳过、`--force` 重做、子目录递归、覆盖源文件、并行处理、重跑幂等；
界面也用 UI 自动化真实点过「开始修复」跑通全流程。

## 7. 环境要求

* **.NET 9 Desktop Runtime**（本机已安装 .NET SDK 9，可直接运行；换机器若提示缺少
  runtime，安装 “.NET Desktop Runtime 9 x64” 即可）。
* **ffmpeg / ffprobe**（ffmpeg 8.0 或更新版本均可）。

## 8. 重新构建

```powershell
.\build.ps1            # 输出到 dist\
.\build.ps1 -Clean     # 清理后重新构建
```

源码结构：`src\Ff.cs`（探测 / 网格判定）、`src\Repair.cs`（方案 / 执行 / 校验）、
`src\FfLocator.cs`（ffmpeg 定位）、`src\MainForm.cs`（界面）、`src\CliRunner.cs`（命令行）。
